# Diseño — Módulo Integración SIGE (RGM SLEP Valparaíso)

> Diseño técnico para que otra IA implemente. Ancla en el código real del RGM
> (FastAPI + psycopg2, schema `matriculas` en Supabase). **No** se ejecutan migraciones hasta
> aprobar la Fase 1. Complementa el documento maestro
> `csv pruebas/libro-digital/Documentacion_Integracion_SIGE_RGM_SLEP.md`.

## 1. Visión general

El módulo añade una cadena **ingestión → validación → staging → normalización → conciliación →
aprobación → aplicación transaccional → RGM**, reutilizando los patrones existentes. La primera
versión cubre matrícula; asistencia queda contemplada en el modelo pero no se implementa.

```text
POST /sige/importaciones  (archivo)
        │
        ▼
  ingestión + detección de formato (XLS-HTML / XML / TXT / CSV)
        │
        ▼  escribe
  sige_importacion (cabecera, hash, estado=CARGADA)
  sige_matricula_staging (1 fila por registro del archivo)
        │
        ▼  POST /sige/importaciones/{id}/validar
  validación por fila → motivos_validacion, sige_error_importacion, estado=VALIDADA
        │
        ▼  POST /sige/importaciones/{id}/conciliar
  conciliación triple-clave vs RGM → sige_conciliacion (clasificación), estado=CONCILIADA
        │
        ▼  GET /sige/importaciones/{id}/preview   (vista previa, sin tocar RGM)
        │
        ▼  POST /sige/importaciones/{id}/aprobar  (individual / lote)
  sige_conciliacion.estado_aprobacion = APROBADA | RECHAZADA
        │
        ▼  POST /sige/importaciones/{id}/aplicar
  transacción: escribe estudiante/matricula + auditoria_matricula, estado=APLICADA
```

Regla de oro: **nada toca producción hasta `aplicar`**, y `aplicar` solo procesa filas
`APROBADA`, en una transacción, escribiendo auditoría.

## 2. Encaje con la arquitectura existente

| Pieza nueva | Patrón que reutiliza | Referencia en el repo |
|---|---|---|
| `routers/sige.py` | `APIRouter(prefix=..., tags=...)` + `include_router` en `main.py` | `routers/matriculas.py` |
| `services/sige_service.py` | SQL crudo con `get_db_connection()`; commit/rollback/finally | `services/matricula_service.py` |
| Parser XLS-HTML | `pandas.read_html(io.BytesIO(bytes), encoding='latin1')` + fallback utf-8 | `procesar_carga_masiva_db` |
| Carga a BD en volumen | cargar a memoria + `execute_values` en chunks de 1000 + commit por chunk + `SET statement_timeout=0` | `importar_registro_2026.py` |
| Normalización RUN | `services.utils.normalizar_rut` + regex inline | `estudiante_service.py` |
| Guards | `verificar_escritura`, `validar_acceso_colegio`, `es_usuario_slep` | `security.py` |
| Migración de tablas | `apply_*.py` idempotente (check-before-create, commit por paso) | `apply_renovacion_migration.py` |
| Auditoría | `INSERT INTO auditoria_matricula (accion,id_usuario,datos_anteriores,datos_nuevos)` | `estudiante_service.py` |

El search_path lo fija `database.py` (`SET search_path TO matriculas, public`), así que las
tablas `sige_*` se crean y usan sin prefijo. Para scripts batch se puede prefijar `matriculas.`
explícitamente (como hace `cargar_asistencia.py`).

## 3. Modelo de datos — DDL PostgreSQL (schema `matriculas`)

> Esta es la propuesta exacta para `apply_sige_staging_migration.py`. Todas las tablas llevan
> prefijo `sige_`, son **aditivas** y no modifican ninguna tabla productiva.

```sql
-- ============================================================
-- sige_importacion: cabecera de cada archivo cargado
-- ============================================================
CREATE TABLE IF NOT EXISTS sige_importacion (
    id_importacion     BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    rbd                VARCHAR(20),
    id_establecimiento INTEGER REFERENCES establecimiento (id_establecimiento),
    anio               INTEGER,
    tipo_fuente        VARCHAR(30) NOT NULL,         -- ver CHECK abajo
    origen_archivo     VARCHAR(30) NOT NULL DEFAULT 'ARCHIVO_MANUAL',
    nombre_archivo     VARCHAR(255),
    hash_archivo       CHAR(64) NOT NULL,            -- SHA-256 hex del binario
    id_usuario         INTEGER REFERENCES usuario (id_usuario),
    fecha_importacion  TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    fecha_corte_origen DATE,                         -- fecha declarada por SIGE si existe
    estado             VARCHAR(20) NOT NULL DEFAULT 'CARGADA',
    total_filas        INTEGER DEFAULT 0,
    filas_ok           INTEGER DEFAULT 0,
    filas_error        INTEGER DEFAULT 0,
    version_parser     VARCHAR(20) DEFAULT 'v1',
    CONSTRAINT chk_sige_imp_tipo CHECK (tipo_fuente IN (
        'NOMINA_XLS_HTML','NOMINA_XML','NOMINA_TXT','NOMINA_CSV',
        'ASISTENCIA_CSV_INDIVIDUAL','ASISTENCIA_CSV_RESUMEN')),
    CONSTRAINT chk_sige_imp_estado CHECK (estado IN (
        'CARGADA','VALIDADA','CONCILIADA','APLICADA','RECHAZADA'))
);

-- Idempotencia: un hash no puede repetirse salvo que la previa fuera RECHAZADA.
-- (Se valida en servicio; opcionalmente índice parcial para acelerar.)
CREATE INDEX IF NOT EXISTS idx_sige_imp_hash   ON sige_importacion (hash_archivo);
CREATE INDEX IF NOT EXISTS idx_sige_imp_estab  ON sige_importacion (id_establecimiento, anio, estado);

-- ============================================================
-- sige_matricula_staging: 1 fila por registro del archivo (crudo + normalizado)
-- ============================================================
CREATE TABLE IF NOT EXISTS sige_matricula_staging (
    id_staging         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_importacion     BIGINT NOT NULL REFERENCES sige_importacion (id_importacion) ON DELETE CASCADE,
    nro_fila           INTEGER NOT NULL,
    -- Crudo
    datos_json         JSONB NOT NULL,               -- fila original tal cual se parseó
    -- Normalizado (lo que usa la conciliación)
    run_ipe_raw        VARCHAR(40),
    run_ipe_norm       VARCHAR(20),                  -- sin puntos/guion, cuerpo+DV
    nombres            VARCHAR(120),
    apellido_paterno   VARCHAR(80),
    apellido_materno   VARCHAR(80),
    sexo               VARCHAR(20),
    fecha_nacimiento   DATE,                         -- puede ser NULL (bloqueante para NUEVO)
    rbd                VARCHAR(20),
    anio_escolar       INTEGER,
    cod_tipo_ensenanza INTEGER,
    cod_grado          INTEGER,
    curso              VARCHAR(60),
    letra_curso        VARCHAR(10),
    fecha_incorporacion DATE,
    fecha_retiro       DATE,
    estado_sige        VARCHAR(30),
    -- Validación
    valido             BOOLEAN NOT NULL DEFAULT FALSE,
    motivos_validacion JSONB DEFAULT '[]'::jsonb,    -- [{campo, codigo, detalle}]
    CONSTRAINT uq_sige_staging_fila UNIQUE (id_importacion, nro_fila)
);
CREATE INDEX IF NOT EXISTS idx_sige_staging_imp   ON sige_matricula_staging (id_importacion);
CREATE INDEX IF NOT EXISTS idx_sige_staging_run   ON sige_matricula_staging (run_ipe_norm);

-- ============================================================
-- sige_conciliacion: 1 fila por diferencia detectada contra el RGM
-- ============================================================
CREATE TABLE IF NOT EXISTS sige_conciliacion (
    id_concil          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_importacion     BIGINT NOT NULL REFERENCES sige_importacion (id_importacion) ON DELETE CASCADE,
    id_staging         BIGINT NOT NULL REFERENCES sige_matricula_staging (id_staging) ON DELETE CASCADE,
    clasificacion      VARCHAR(20) NOT NULL,
    id_estudiante_rgm  INTEGER REFERENCES estudiante (id_estudiante),
    id_matricula_rgm   INTEGER REFERENCES matricula (id_matricula),
    diferencias_json   JSONB DEFAULT '{}'::jsonb,    -- {antes:{...}, despues:{...}}
    accion_propuesta   VARCHAR(40),                  -- CREAR_MATRICULA / ACTUALIZAR_CURSO / MARCAR_RETIRO / NINGUNA
    severidad          VARCHAR(10) DEFAULT 'INFO',   -- INFO / ALERTA / BLOQUEO
    estado_aprobacion  VARCHAR(15) NOT NULL DEFAULT 'PENDIENTE',
    id_usuario_aprueba INTEGER REFERENCES usuario (id_usuario),
    fecha_aprobacion   TIMESTAMPTZ,
    CONSTRAINT chk_sige_conc_clasif CHECK (clasificacion IN (
        'NUEVO','COINCIDENTE','CAMBIO_CURSO','RETIRO','CONFLICTO','REVISAR')),
    CONSTRAINT chk_sige_conc_aprob CHECK (estado_aprobacion IN (
        'PENDIENTE','APROBADA','RECHAZADA','APLICADA'))
);
CREATE INDEX IF NOT EXISTS idx_sige_conc_imp    ON sige_conciliacion (id_importacion, clasificacion);
CREATE INDEX IF NOT EXISTS idx_sige_conc_aprob  ON sige_conciliacion (id_importacion, estado_aprobacion);

-- ============================================================
-- sige_error_importacion: errores por fila (reporte)
-- ============================================================
CREATE TABLE IF NOT EXISTS sige_error_importacion (
    id_error           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_importacion     BIGINT NOT NULL REFERENCES sige_importacion (id_importacion) ON DELETE CASCADE,
    nro_fila           INTEGER,
    campo              VARCHAR(60),
    codigo_error       VARCHAR(40),
    detalle            TEXT,
    fecha              TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_sige_error_imp   ON sige_error_importacion (id_importacion);
```

### Notas de diseño del modelo
- **Triple clave de conciliación**: `(id_estudiante, id_establecimiento, anio_escolar)`. El RUN
  nunca es clave única histórica (igual que el RGM). `run_ipe_norm` solo resuelve el
  `id_estudiante`.
- **`datos_json`** conserva el registro original → trazabilidad y rectificación (nunca se
  destruye el dato de origen).
- **`ON DELETE CASCADE`** desde `sige_importacion` permite descartar una importación `RECHAZADA`
  completa sin huérfanos; las `APLICADA` se conservan por política.
- **`fecha_nacimiento` NULL permitido en staging** porque es el bloqueante conocido: un `NUEVO`
  sin fecha de nacimiento va a `REVISAR`, no falla.
- Las tablas de **asistencia** (etapa 2) NO se crean ahora; `tipo_fuente` ya reserva sus valores.

## 4. Adaptadores de formato (parser configurable)

Diseño de puertos/adaptadores para no acoplar la conciliación al formato de origen.

```
detectar_formato(nombre, bytes) -> tipo_fuente
parse(bytes, tipo_fuente) -> List[FilaCanonica]
```

| Formato | Detección | Librería | Nota |
|---|---|---|---|
| XLS-HTML | contenido empieza con `<` / `<table` / `<html` | `pandas.read_html` latin1→utf-8 | caso real SIGE |
| XML | empieza con `<?xml` | `xml.etree` o `pandas.read_xml` | validar estructura real cuando llegue muestra |
| TXT | delimitado (detectar `;`/`\t`/`|`) | `csv`/`pandas` | mapeo versionado |
| CSV | extensión `.csv`, separador `;` | `pandas.read_csv(sep=';')` | nómina/asistencia |

**Mapeo de columnas versionado**: cada `tipo_fuente`+versión tiene un diccionario
`columna_origen → campo_canónico`. Vive en código (constante) para el MVP; se puede externalizar
a una tabla `sige_field_mappings` en el futuro (mencionada en el maestro como
`integration_field_mappings`). La `FilaCanonica` mínima:

```
run_ipe, nombres, apellidos, sexo, fecha_nacimiento, rbd, anio_escolar,
cod_tipo_ensenanza, cod_grado, curso, letra_curso, fecha_incorporacion,
fecha_retiro, estado_sige
```

## 5. Validación (Requisito 3 y 11bis)

Por fila, acumulando en `motivos_validacion` y `sige_error_importacion`:

| Validación | Regla | Falla → |
|---|---|---|
| Obligatorios | RUN, RBD, año, curso/grado presentes | ALERTA, `valido=false` |
| RUN | `normalizar_rut` + dígito verificador correcto | ALERTA |
| RBD | existe en `establecimiento` | REVISAR (no crea estab.) |
| Código enseñanza | 110/310 conocidos; otros → "revisar código" | INFO (no descarta) |
| Fecha válida | no día inexistente, no `1900-*` centinela | ALERTA |
| fecha_nacimiento (si NUEVO) | presente | REVISAR (bloqueante p/alta) |

Al terminar: `sige_importacion` actualiza `total_filas/filas_ok/filas_error`, estado `VALIDADA`.

## 6. Conciliación (Requisito 4)

Pseudocódigo del clasificador por fila válida:

```
est = buscar_estudiante_por_run(run_ipe_norm)          # match normalizado
if est is None:
    if fecha_nacimiento is None: -> REVISAR (no se puede crear, NOT NULL)
    else:                        -> NUEVO (accion: CREAR_MATRICULA)
else:
    mat = buscar_matricula(est.id, id_establecimiento, anio_escolar)   # triple clave
    if mat is None:
        -> NUEVO (crear matrícula para estudiante existente)
    elif fila.fecha_retiro válida and mat.estado == 'Activa':
        -> RETIRO (accion: MARCAR_RETIRO)
    elif (mat.curso, mat.cod_tipo_ensenanza) != (fila.curso, fila.cod_ens):
        -> CAMBIO_CURSO (accion: ACTUALIZAR_CURSO)
    elif identidad_ambigua(run -> varios estudiantes):
        -> CONFLICTO
    else:
        -> COINCIDENTE (accion: NINGUNA)
```

Cada resultado escribe `sige_conciliacion` con `diferencias_json = {antes, despues}`. La
conciliación es **solo lectura sobre el RGM**. Al final, estado `CONCILIADA`.

## 7. Aprobación y aplicación (Requisitos 6 y 7)

- **Aprobar**: actualiza `estado_aprobacion` (individual o por lote con filtro). `CONFLICTO` no se
  aprueba por lote ciego.
- **Aplicar** (transacción única):
  - `NUEVO`: upsert `estudiante` por `run_ipe` (`ON CONFLICT (run_ipe) DO UPDATE` con COALESCE);
    crear `matricula` reutilizando la lógica de correlativo y `obtener_rango_curso` (idealmente
    llamando a la función existente, no reimplementando la jerarquía).
  - `CAMBIO_CURSO`: aplicar como el RGM lo hace hoy (nuevo correlativo en curso destino, traza en
    observaciones).
  - `RETIRO`: marcar estado según reglas del RGM; **nunca** retiro automático por ausencia en
    nómina.
  - Cada cambio → `INSERT INTO auditoria_matricula`.
  - Filas aplicadas: `estado_aprobacion='APLICADA'`; importación `estado='APLICADA'`.
- Error en cualquier fila → `rollback` de toda la aplicación (atomicidad).

## 8. Endpoints (contrato REST)

Prefijo `/sige`. Todos requieren JWT; los de escritura `Depends(verificar_escritura)`; alcance
por `validar_acceso_colegio` / check SLEP para multi-RBD.

| Método | Ruta | Rol | Descripción |
|---|---|---|---|
| POST | `/sige/importaciones` | SLEP (multi-RBD) / Colegio (su RBD) | Carga archivo → staging |
| POST | `/sige/importaciones/{id}/validar` | escritura | Valida filas |
| POST | `/sige/importaciones/{id}/conciliar` | escritura | Clasifica vs RGM |
| GET  | `/sige/importaciones/{id}/preview` | lectura (rol/RBD) | Diferencias por clasificación |
| POST | `/sige/importaciones/{id}/aprobar` | escritura | Aprueba/rechaza (individual/lote) |
| POST | `/sige/importaciones/{id}/aplicar` | escritura | Aplica aprobadas (transacción) |
| GET  | `/sige/importaciones` | lectura (rol/RBD) | Lista importaciones + estado |
| GET  | `/sige/importaciones/{id}/reporte` | lectura (rol/RBD) | Totales + errores |

Esquemas Pydantic nuevos en `schemas.py` (p. ej. `SigeAprobacionRequest {ids:[], decision:
'APROBADA'|'RECHAZADA', filtro?}`). No se tocan los schemas existentes.

## 9. Seguridad y datos de menores
- Guards reutilizados (sección 2). Colegio solo su `id_establecimiento`; multi-RBD solo SLEP.
- Logs: nunca RUN/nombres/documentos. Referenciar por `id_staging`/`id_estudiante`.
- Tests exclusivamente con **datos sintéticos** (ver `tasks.md` y fixtures).
- Archivos: si se persiste el original, usar `storage_service` (local/S3) con política de
  retención; para el MVP basta `hash_archivo` + `datos_json` por fila.

## 10. Reporte (Requisito 9)
`GET /sige/importaciones/{id}/reporte` devuelve:
```json
{
  "importacion": {"id":..., "rbd":..., "anio":..., "fecha_importacion":..., "fecha_corte_origen":...},
  "totales": {"cargadas":N,"validas":N,"con_error":N,"aplicadas":N},
  "por_clasificacion": {"NUEVO":n,"COINCIDENTE":n,"CAMBIO_CURSO":n,"RETIRO":n,"CONFLICTO":n,"REVISAR":n},
  "cuadre_fn2FA": {"matriculados":N,"bajas":N,"inscritos":N},   // calidad (ref. función de verificación)
  "errores": [{"nro_fila":...,"campo":...,"codigo_error":...,"detalle":...}]
}
```
El reporte DEBE indicar el desfase: muestra `fecha_importacion` y `fecha_corte_origen`; no afirma
"al día".
