# Arquitectura del Sistema de Matrículas — SLEP Valparaíso

## Resumen
Sistema de Registro General de Matrículas (RGM) del SLEP Valparaíso.
- **Backend**: FastAPI + psycopg2 (SQL crudo, sin ORM). Carpeta `backend/`.
- **Frontend**: React + Vite + TypeScript + TailwindCSS. Carpeta `frontend-matriculas/`.
- **Base de datos**: Supabase (PostgreSQL).

Dominios objetivo (producción): `matricula.slepvalparaiso.gob.cl` y `rgm.slepvalparaiso.gob.cl`.

## Base de datos (Supabase)
- Proyecto Supabase: `directorio_escolar_slep`, ref `gyhihuovussdauehmeuk`.
- Es una base **compartida**: el schema `public` lo usan OTROS sistemas del SLEP
  (reservas de salas, OIRS/SIAC, funcionarios, documentos). NO tocar esas tablas.
- El sistema de matrículas vive **aislado en el schema `matriculas`**.

### Tablas del schema `matriculas`
| Tabla | Descripción |
|---|---|
| `estudiante` | ~34k estudiantes (run_ipe, nombres, fecha_nac, domicilio, id_apoderado_principal) |
| `matricula` | ~91.7k matrículas (2022–2026). FK a estudiante, establecimiento, usuario, catálogos |
| `apoderado` | Apoderados |
| `establecimiento` | 66 colegios. Columna `slep_establecimiento_id` enlaza (FK) a `public.slep_establecimientos` por RBD |
| `catalogo_grado` | Catálogo de grados |
| `catalogo_tipo_ensenanza` | Catálogo de tipos de enseñanza |
| `usuario` | Usuarios del sistema (email, nombre, rol, id_establecimiento, activo, password_hash) |
| `acceso_establecimiento` | Control de acceso Google: correo → id_establecimiento → rol (multi-funcionario por colegio) |
| `auditoria_matricula` | Bitácora (creada vacía; los ~284k históricos del backup NO se migraron) |

### Convenciones de datos importantes
- Nombres de tabla en **singular** (`estudiante`, `matricula`, ...). Las queries del
  backend usan estos nombres y dependen del `search_path`.
- PKs con `GENERATED BY DEFAULT AS IDENTITY`. Las secuencias ya se ajustaron con `setval`.
- `establecimiento.rbd` es varchar (ej '1506'); en `public.slep_establecimientos` el rbd es integer.

## Conexión backend → BD
- `backend/database.py` → `get_db_connection()` conecta vía `DATABASE_URL` (pooler de
  Supabase) y fija `SET search_path TO matriculas, public`.
- Config por variables de entorno en `backend/.env` (ver `.env.example`).
- Migración de datos original: se cargó desde `C:\backup_rgm.sql` (pg_dump) con un
  script Python/psycopg2 por lotes. Ese archivo y los temporales ya no se usan.

## MCP de Supabase
- Está instalado el power `supabase-hosted`. Usar `project_id = gyhihuovussdauehmeuk`.
- Para DDL usar `apply_migration`; para consultas `execute_sql`.
- Al crear/modificar tablas del sistema, hacerlo SIEMPRE en el schema `matriculas`.
